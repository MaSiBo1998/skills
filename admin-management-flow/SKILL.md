# 管理后台开发流程

本 skill 用于管理后台类项目的普通功能开发和接口接入。优先贴合目标项目现有 Vue/Element UI、接口封装、权限、i18n、布局和构建方式，不套用 H5 进件/首复贷流程。

## 工作流程

1. 先读项目事实：
   - 查看 `package.json`、入口、布局、接口封装、store、router、i18n 和相关业务目录。
   - 用 `rg` 搜索相同业务、相似按钮/弹窗/toast/轮询/权限模式。
   - 确认用户信息字段、角色字段、接口请求工具、响应拦截器和错误处理方式。
2. 明确需求契约：
   - 接口路径、method、入参、响应字段、状态枚举、时间格式、是否以后端为准。
   - 展示范围：角色、菜单、页面、全局布局或单页组件。
   - 自动同步方式：初始化请求、轮询间隔、本地计时、刷新后的恢复策略。
   - 若用户提供新接口文档或字段替换需求，可参考 `h5-api-mapping` 的字段映射表方法；但后台路由、权限、Element UI 页面和业务交互仍由本 skill 实现。
3. 按现有模式实现：
   - API 封装放到对应 `src/api/<domain>`，复用项目请求工具。
   - 页面级需求改对应 view；全局顶部/布局需求优先封装独立组件，再挂到 layout/navbar。
   - 角色权限只在前端做展示控制时，使用登录用户或现有 permission 工具；业务状态仍以后端接口为准。
   - 多语言项目必须补齐当前启用语言；默认语言环境的文案优先满足业务指定语种。
   - 新增 i18n 文案前必须先搜索现有翻译 key 和文案，已有可复用翻译时不要重复定义。
   - i18n key 归类按用途放置：菜单/路由相关放 `route`，按钮相关放 `btn`，其他较短表格/字段/状态文案优先放 `table`，较长提醒/提示说明放 `title`。
4. 交互规则：
   - 弹窗、radio、按钮 loading、禁用态、toast/notify 使用项目现有 Element UI 风格。
   - 对轮询和计时分别管理 timer，组件销毁时清理。
   - 接口失败时不伪造成功状态，保留原状态并交给现有拦截器或本地提示处理。
   - 后端返回 toast/systemToast 时优先展示后端文案；系统自动提示需用时间戳或唯一 key 去重。
5. 验收：
   - 先跑触达文件 lint；若全量 lint 被历史问题挡住，明确列出非本次引入的文件。
   - 跑项目构建验证 Vue 模板和打包；记录已有 warning，不把无关 warning 当成本次失败。
   - 对全局顶部组件额外关注窄屏、头像/语言切换挤压、按钮文字溢出。
   - 交付前按 `h5-testing-checklist` 的场景 I 管理后台专项验收补充检查路由/菜单、权限、接口数据流、Element UI 交互、i18n 和异常态。

## 本次沉淀案例

催收后台“催收员工作状态”需求应按以下模式处理：

- 顶部状态条属于全局布局能力，新增独立组件并挂到 `Navbar`，不要把所有状态逻辑写进导航组件。
- 状态以后端 current 接口为准；前端只做展示、按钮控制、本地暂停计时和轮询校准。
- `canPause/canWork` 控制按钮可点击；异常切换态只提示“不支持切换”，不调用业务接口。
- 初始化立即请求状态，按用户指定间隔轮询；暂停计时可以 1 秒本地递增。
- 手动 pause/work 成功后优先应用接口返回状态；返回不完整时重新请求 current。

## 交付说明

交付时说明改了哪些模块、接口、组件和语言文件；列出 lint/build 结果和管理后台专项验收结果。如果全量 lint 或构建存在历史 warning/error，必须区分“本次触达文件通过”和“仓库既有问题”。
