# 输入收集（通用模块）

所有前端工作流场景共用的输入收集步骤。默认策略是先查再问：先从用户输入、当前工作目录、项目文件、接口文档、设计图、发布配置和已有 checkpoint 推断信息；只有缺失信息会阻断继续执行或涉及高风险业务结论时才询问用户。

## 收集顺序

1. 读取用户需求和当前工作目录，确认是否已经在目标项目内。
2. 查找项目证据：`package.json`、构建脚本、`vite.config.*`、路由、页面目录、接口封装、环境变量、`public`、`design/`、`release-env`、后台权限/菜单文件。
3. 读取相关材料：接口文档、协议文档、设计图、线上链接、WebView 入口、已有 `.workflow-checkpoint.json`。
4. 将已确认事实写入 checkpoint `context.discovered_facts`，将默认选择写入 `context.assumptions`。
5. 只对阻塞项提问，并记录到 `context.blocking_questions`。

禁止泛问“请提供完整信息”。每个问题必须说明已查到什么、缺什么、为什么当前缺口会阻塞继续执行。

## 输入矩阵

| 场景 | 优先自动推断 | 缺失但不阻塞 | 缺失会阻塞 |
| --- | --- | --- | --- |
| A 架构改造 | 项目根目录、是否 Vite/npm、已有 vendor 架构、构建脚本 | 目标构建命令可用默认 build/dev 脚本 | 找不到项目根目录或无法判断技术栈 |
| B 功能/API 开发 | 项目根目录、目标页面/模块、接口封装、本次更像页面还是接口 | 产品名、业务国家、非必要接口文档 | 没有业务目标、找不到目标模块、字段替换却没有文档且代码无来源 |
| C 首复贷开发 | 首复贷路由、状态枚举、订单/还款/额度页面、现有接口 | 产品名、业务国家可从配置或文案推断时不问 | 状态流业务结论不明、涉及资金/风控/还款规则且代码无法判断 |
| D 进件开发 | Apply/Entry 路由、步骤配置、原生桥接、国家 profile、现有接口 | 产品名、国家、接口文档缺失但不影响当前修改 | 步骤顺序、国家差异或原生回调语义无法从代码判断 |
| E 官网/协议/挂载 H5 | 项目根目录或 `public` 目录、协议/客服页面、协议文档、挂载路径 | 协议链接、WebView 入口、线上域名 | 既没有协议文档/目标页面需求，也找不到输出位置 |
| F 设计图复原 | 项目根目录、`design/` 文件夹、设计图文件、目标路由、可复用 assets | 产品名、业务国家 | 找不到设计图或目标页面/路由无法推断 |
| G 国家发布 | 项目根目录、`release-env`、构建脚本、当前分支 | 手动指定国家 | 找不到发布国家且用户要求继续发布 |
| H 工作流自我更新 | 用户指出的问题、相关 skill、归属表、运行时同步状态、automation memory、已有 checkpoint、轻量规格、编排审查目标、回归样例范围 | 目标 skill 未指定时由工作流判断；评估样例默认使用当前回归集 | 需要固化高风险业务结论但用户未给结论 |
| I 管理后台开发 | 项目根目录、目标页面/模块、路由菜单、权限、接口封装、Element UI/Vue 版本 | 角色权限、菜单入口、i18n 范围可从代码推断时不问 | 找不到目标模块或权限/菜单变更会影响真实角色且代码无依据 |
| J 飞书前端告警 | 项目根目录、告警范围、monitor/error boundary/loading 组件、API 配置 | 线上 H5 域名配置可先新增为空配置并列为待验 | 缺少后端告警代理接口且代码无法推断；需要立即完成真实生产收发验证或发布但缺少线上 H5 域名 |
| K 未知/复合需求分析 | 项目类型、候选页面/模块、相似场景、可用子 skill、风险点 | 产品名、国家、完整需求细节 | 没有项目路径、没有目标页面/模块、没有业务目标，导致无法探索 |

## 执行规则

- 列出已推断事实、默认假设、阻塞问题；无阻塞问题时继续执行，不等待用户确认。
- 将收集到的输入路径写入 checkpoint context（如 `product_name`、`country`、`api_doc_path`、`project_config`、`target_route`、`release_env_path`、`discovered_facts`、`assumptions`、`blocking_questions`）。
- 场景 B 普通功能/API 开发未确认产品名或国家时可以继续；若用户提供或代码可推断则写入 checkpoint。
- 场景 F 设计图复原未确认产品名或国家时可以继续；目标页面或路由无法判断时才询问。
- 场景 I 管理后台未确认角色权限或菜单入口时先读取现有项目实现；若无法从代码判断且会影响真实权限/菜单，再询问。
- 场景 J 若缺少后端告警代理接口且代码中无法推断，必须询问具体缺失项；不要用浏览器端飞书 webhook 代替。
- 场景 J 若缺少可用于判断线上页面 host 的 H5 域名配置，可以先新增显式 H5 host 配置并让空配置默认不发送，交付列为待配置/待验；只有用户要求真实生产收发验证或发布时，才把实际线上 H5 域名作为阻塞问题询问。不得用 API 域名、通用 HTTP baseURL 或飞书 webhook 域名判断页面环境。
- 场景 H 巡检默认使用 `workflow-self-improvement/references/workflow-regression-evaluation.md` 的当前样例集；用户未指定评估集时不阻塞，样例数量和通过线按该文件的样例表动态计算。
- 场景 H 来自自动化续跑时，必须先读取 automation memory 和 `.workflow-checkpoint.json`，并把本轮 memory 路径、读取状态、写回状态、剩余漂移和下一轮关注点写入 checkpoint。
- 场景 K 必须先完成最小探索，再决定回落到 A-J 或继续询问阻塞项；K 不能作为最终交付归属。
- 若场景 D 的国家为 `Guatemala` / `GT` / `危地马拉`，在后续步骤加载 `h5-apply-flow/references/country-guatemala.md`
- 若场景 D 的国家为墨西哥、哥伦比亚或其他国家，不能套用危地马拉规范；要求用户提供该国家差异或按通用 Apply 流程执行

## 可选：项目配置信息

完成当前场景必填项收集后，若涉及接口/字段替换或新项目迁移，先从目标项目代码、环境变量、接口文档和用户已给材料中提取项目配置；不要因为可选项目配置缺失而打断流程。

- **用户已提供配置** → 按 `h5-api-mapping/references/project-config.md` 的配置项清单归档，写入 checkpoint context 的 `project_config` 字段。
- **代码或文档可推断配置** → 使用项目现有配置，记录来源和不确定项。
- **缺失配置会阻断接口联调、加密、登录态或发布判断** → 只询问缺失的阻断项，不泛问“是否需要提供项目配置信息”。
- **缺失配置不阻断当前开发** → 标记为待验或待确认，继续使用代码中现有配置。
