# 输入收集（通用模块）

所有前端工作流场景共用的输入收集步骤。按场景收集必填项，可选项缺失不得阻断流程。

## 输入矩阵

| 场景 | 必填输入 | 可选输入 |
| --- | --- | --- |
| A 架构改造 | 项目根目录、是否 Vite/npm、是否已有 vendor 架构 | 目标构建命令 |
| B 功能/API 开发 | 项目根目录、本次需求类型 | 产品名、业务国家；接口文档仅字段替换或接口适配时必填 |
| C 首复贷开发 | 项目根目录、产品名、业务国家、本次需求类型 | 接口文档仅新文档/字段替换时必填 |
| D 进件开发 | 项目根目录、产品名、业务国家、本次需求类型 | 接口文档仅新文档/字段替换时必填 |
| E 官网/协议/挂载 H5 | 协议文档或目标页面需求、项目根目录或目标 `public` 目录 | 协议链接、挂载路径、WebView 入口 |
| F 设计图复原 | 项目根目录、`design/` 文件夹、目标页面或路由 | 产品名、业务国家 |
| G 国家发布 | 项目根目录、`release-env` | 手动指定国家 |
| H 工作流自我更新 | 要沉淀的问题 | 目标 skill；未指定时由工作流判断 |
| I 管理后台开发 | 项目根目录、目标页面/模块、本次需求类型 | 角色权限、接口文档、菜单入口、i18n 范围 |
| J 飞书前端告警 | 项目根目录、告警触发范围、后端告警代理接口或接口文档 | 线上 H5 域名配置、已有 monitor/error boundary/loading 组件 |

## 执行规则

- 列出已拿到和缺失的输入
- 缺失当前场景必填输入时明确列出并要求补充
- 将收集到的输入路径写入 checkpoint context（如 `product_name`、`country`、`api_doc_path`、`project_config`、`target_route`、`release_env_path`）
- 场景 B 普通功能/API 开发未确认产品名或国家时可以继续；若用户提供则写入 checkpoint
- 场景 F 设计图复原未确认产品名或国家时可以继续；目标页面或路由无法判断时必须询问
- 场景 I 管理后台未确认角色权限或菜单入口时可以先读取现有项目实现；若无法从代码判断，必须在开发前询问
- 场景 J 若缺少后端告警代理接口或可用于判断线上页面 host 的 H5 域名配置，且代码中无法推断，必须询问具体缺失项；不要用浏览器端飞书 webhook 或 API 域名判断替代
- 若场景 D 的国家为 `Guatemala` / `GT` / `危地马拉`，在后续步骤加载 `h5-apply-flow/references/country-guatemala.md`
- 若场景 D 的国家为墨西哥、哥伦比亚或其他国家，不能套用危地马拉规范；要求用户提供该国家差异或按通用 Apply 流程执行

## 可选：项目配置信息

完成当前场景必填项收集后，若涉及接口/字段替换或新项目迁移，先从目标项目代码、环境变量、接口文档和用户已给材料中提取项目配置；不要因为可选项目配置缺失而打断流程。

- **用户已提供配置** → 按 `h5-api-mapping/references/project-config.md` 的配置项清单归档，写入 checkpoint context 的 `project_config` 字段。
- **代码或文档可推断配置** → 使用项目现有配置，记录来源和不确定项。
- **缺失配置会阻断接口联调、加密、登录态或发布判断** → 只询问缺失的阻断项，不泛问“是否需要提供项目配置信息”。
- **缺失配置不阻断当前开发** → 标记为待验或待确认，继续使用代码中现有配置。
