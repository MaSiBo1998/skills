# 首复贷流程代际

首复贷先判业务场景为 First/ReLoan，再判流程代际。参考项目只能用于对照，不是唯一事实来源；参考项目缺失时仍按本文件的稳定合同推进。

## 公共合同

任何首复贷流程都至少按以下合同处理：

- 首页状态：读取首页/状态接口，识别首贷、复贷、审核中、审核拒绝、未确认、放款中、放款失败、还款期、App 列表等业务状态。
- 数据源区分：首贷、复贷、授信订单、金融订单、产品列表、还款计划不能混用；目标项目类型和 KB contract 优先。
- 申贷确认：金额、期限、期数、产品 ID、设备/广告/风控信息按目标项目真实结构提交。
- 还款/支付：支付方式、外链、非 URL 凭证、复制兜底、服务费、渠道图标、返回入口形成闭环。
- banner 与埋点：设计图缺失不等于删除已有 banner、轮询、bridge 跳转、按钮回调、刷新逻辑或埋点。
- 原生交互：首复贷可能有原生方法，也可能是独立 H5；只有出现原生方法、bridge 或 window 回调证据时才判定 App 内嵌。
- 兼容与性能：低版本浏览器、关键布局禁用 `gap`、安全区兜底、首屏分包和辅助能力延后初始化按公共验收执行。
- 精确结构：用户、KB contract 或现有类型明确结构时，按固定结构取值或解析；不要新增多层字段探测、旧字段兼容或本地文案兜底。

## 旧流程

旧流程参考项目待用户补充。当前只沉淀分类，不沉淀具体字段、接口或状态码。

在用户补充前，稳定处理规则如下：

- 如果用户明确说旧流程，先按“首复贷公共合同 + 目标项目证据”执行。
- 不套用当前新流程里的具体状态组件、字段名、接口路径或路由名。
- 必须从目标项目读取首页状态、订单、产品、还款、风控、埋点和 bridge 的真实实现。
- 若目标项目证据不足以判断高风险业务规则，例如资金、还款、风控、发布结论，只问最小阻塞问题。

## 新流程

当前 `h5-first-reloan-flow` 已沉淀的状态流、订单、还款、支付过渡页、App 列表、banner、风控上传和字段精确结构规则，默认归属新流程。

稳定处理规则：

- 先复用目标项目现有状态分发、数据源、路由、service、store、组件和命名。
- 设计图只作为视觉输入，不删除业务模块。
- 接口结构明确时按固定结构直接取值。
- 涉及原生交互时写入 `webview`，同一改动包含真实输入项时追加 `form-input`，真实设备待验由公共区域验收承接。

## 参考项目缺失 fallback

如果后续补充的旧流程参考项目或当前新流程参考项目不可用：

1. 不因参考项目缺失阻断。
2. 先读取目标项目证据：`package.json`、路由、首页、状态页、订单/还款/支付页面、API、types、bridge、风控模块、埋点、design、checkpoint。
3. 若用户已说明旧流程或新流程，按对应稳定处理规则执行，并在交付中记录“参考项目不可用，已按抽象合同 + 目标项目证据处理”。
4. 若旧/新流程无法从用户输入和目标项目证据判断，才问一个最小阻塞问题：“本次首复贷按旧流程还是新流程处理？”
5. 不凭记忆补参考项目里的字段、状态码、接口、路由或组件名。

## 禁止项

- 不把参考项目路径当成必须存在的运行依赖。
- 不把新流程状态/字段硬套到旧流程。
- 不因为出现“首复贷”就判定为 App 内嵌；只有原生交互证据才能判定。
