# 首复贷开发场景

本文件是首贷/复贷开发的独立场景参考。凡涉及首贷、复贷、状态流、订单状态、产品详情、未确认贷款、放款中、放款失败、还款期、App 列表、额度确认、风控上传或借款协议，都必须使用 `h5-first-reloan-flow`，先读取本文件，再读取 `status-flow.md`。

本工作流不依赖任何具体项目。文中出现的字段、组件、路由和接口名称只作为 `参考项目` 的示例命名，用来说明业务语义如何落地；在其他项目中必须使用本项目真实结构，不能直接套用示例字段。普通首复贷需求只基于现有代码补充业务；只有用户明确要求用新接口文档、新字段或新接口地址替换时，才触发接口/字段映射。

## 场景边界

首复贷不是普通接口开发，也不是 Apply 步骤进件开发。它负责用户从首页状态、产品列表、产品详情到借款确认、放款、失败、还款的完整状态流。

典型示例：

- “首复贷未确认页补一个按钮，不换接口文档”：场景 C，直接复用现有首复贷代码补充页面/交互，不调用 `h5-api-mapping`。
- “复贷返回增加挽留弹窗，不换字段”：场景 C，修改返回拦截、弹窗和埋点，不建立字段映射。
- “首复贷换新接口文档、字段名和接口地址”：场景 C 业务归属，但先调用 `h5-api-mapping` 完成同结构字段/API 替换，再回到首复贷专项验收。

典型修改范围按语义识别，不按固定路径识别：

| 语义模块 | 常见文件形态 | 示例命名 |
| --- | --- | --- |
| 首页状态入口 | 首页页面、首页状态调度组件 | `src/pages/Home/`、`StatusView` |
| 复贷详情入口 | 产品详情页、订单详情页、状态详情页 | `src/pages/Status/`、`/status?appName=xxx` |
| 状态组件 | 审核、未确认、放款、失败、还款、产品列表组件 | `src/components/status/` |
| 首复贷 API | 首页、产品详情、申贷、还款、埋点接口 | `services/api/home.ts`、`product.ts`、`order.ts` |
| 类型定义 | 首页数据、产品、授信订单、金融订单、还款计划 | `types/home.ts` |
| 原生桥接 | App WebView bridge hook / utility | `useAppBridge` |
| 风控埋点 | 风控 hook、store、上传工具 | `useReduxRiskTracking`、`riskSlice` |
| 路由 | 首页、状态详情、支付过渡、帮助页 | `router/routes.tsx` |

不要把首复贷状态组件拆成两套重复页面；首贷和复贷优先复用组件，通过数据源、状态分支、路径、埋点和原生回调表达差异。

## 执行流程

1. 确认产品名、国家、项目根目录、本次需求类型和是否需要 vendor 架构。vendor 架构为可选项，默认不做；只有用户确认、checkpoint 中 `vendor_enabled=true` 或项目现有架构要求时才执行。
2. 读取目标项目约束：`AGENTS.md`/`CLAUDE.md`/README、`package.json`、路由、首页、状态页、类型、API、bridge、风控模块。
3. 判断是否涉及接口/字段替换：
   - 业务补充：不重新建立项目适配映射，直接复用现有首复贷入口、状态分发、类型、API 和 bridge。
   - 文档替换：用户明确提供新接口文档、新字段、新接口地址或新项目迁移要求时，先由 `h5-api-mapping` 输出字段映射表并完成同结构混淆字段替换。
4. 加载 `status-flow.md`，按本次需求影响范围检查 Home 状态、Status 状态、App 列表和产品详情的数据流。
5. 如本次涉及接口/字段替换，对照接口文档输出字段映射，至少覆盖首页、产品详情、申贷、还款、通用埋点；如不涉及则跳过。
6. 如本次涉及类型字段替换，建立或更新类型定义，保留混淆字段的业务注释，避免只按字段名猜语义。
7. 更新状态分发：
   - 首贷入口使用“顶层用户状态码”分发。
   - 复贷详情入口先区分“金融订单/还款订单”和“授信订单/申请订单”，再用内部状态分发。
8. 更新共享状态组件，例如未确认、审核中、审核拒绝、放款中、放款失败、还款、App 列表。
9. 更新原生桥接和风控埋点。
10. 执行首复贷专项验收和通用 14 项验收。

## 按需字段/接口映射

只有本次涉及新接口文档、新字段、新接口地址、新项目迁移或用户明确要求替换字段时，才需要把以下语义映射到目标项目真实代码。普通首复贷业务补充只复用现有实现，不要求重新输出完整映射表。

| 语义 | 需要确认的问题 | `参考项目` 示例 |
| --- | --- | --- |
| 首贷入口 | 哪个页面请求首页状态并渲染首贷状态组件 | `/`、`getHomeData()`、`HomeData.visor` |
| 复贷入口 | 哪个页面按产品或订单拉详情 | `/status?appName=xxx`、`getProductDetail({ appName })` |
| 产品列表 | 首页多产品列表字段是什么，启用/未启用如何区分 | `attorn[]`、`spectrin` |
| 顶层状态 | 首页用户状态码字段是什么 | `visor` |
| 授信订单 | 待确认、审核、拒绝、放款中的数据节点是什么 | `mpls` |
| 金融订单 | 放款、失败、还款的数据节点是什么 | `trophy` |
| 产品配置 | 金额、天数、期数、产品 ID、营销产品 ID 字段是什么 | `maulers`、`kinkle`、`seine` |
| 申贷接口 | 提交确认贷款需要哪些参数 | `toSubmitOrder(params)` |
| 还款接口 | 支付、还款方式、还款计划来自哪里 | `toPayMoney`、`trophy.dominant` |
| 原生 bridge | 是否已有统一 hook / utility，消息协议是什么 | `useAppBridge`、`method/value` |
| 风控埋点 | 事件码、停留时长、提交结果、上传时机如何定义 | `useReduxRiskTracking` |
| 返回拦截 | 复贷未确认是否需要挽留弹窗 | `RetentionPopup` |

如果字段是混淆命名且本次需要替换，必须以接口文档、类型注释、现有页面使用方式三方交叉确认语义；不能仅凭字段名翻译或猜测。

## 数据源规则

首贷默认来自首页接口结果，复贷默认来自产品详情接口结果。具体字段按目标项目现有实现读取；只有本次涉及字段替换时，才按字段映射表替换。

| 流程 | 页面语义 | 数据入口语义 | `参考项目` 示例路径 |
| --- | --- | --- | --- |
| 首贷 | 首页 | 首页状态接口 | `HomeData.visor`、`HomeData.attorn[0]`、`attorn[0].maulers`、`attorn[0].misdate` |
| 复贷 | 产品/订单详情页 | 产品详情接口 | `AppList.outpace`、`AppList.mpls`、`AppList.trophy`、`mpls.maulers`、`trophy.dominant` |

组件内需要区分首贷/复贷时，优先使用明确上下文或路由来源；如果项目已有约定，可复用现有判断，但必须集中检查所有数据路径是否同步切换。

## 状态分发规则

首贷首页状态使用“顶层用户状态码”分发。`参考项目` 示例：

```
100 -> EntryForm
150 -> AuditCountdown
200 -> AuditPending
300 -> ExamineReject
310/320 -> IdCardOrFaceReject
370 -> EntryForm 或 reload 后继续进件
400 -> LoanUnconfirmed
500 -> LoanInProgress
510 -> LoanFailed
600 -> AppList
```

复贷详情页不要直接套用首页顶层状态；必须先区分订单类型。`参考项目` 示例：

```
金融订单: outpace === 300
  trophy.outpace === 100 -> LoanInProgress
  trophy.outpace === 200 -> LoanFailed
  trophy.outpace === 300 -> Payment

授信订单: outpace !== 300
  mpls.outpace === 0 && mpls.orexis === 0 -> LoanUnconfirmed
  mpls.outpace === 0 && mpls.orexis === 1 -> AuditCountdown
  mpls.outpace === 200 || mpls.outpace === 300 -> AuditPending
  mpls.outpace === 400 -> ExamineReject
  mpls.outpace === 600 -> LoanInProgress
```

新增或变更状态码时，必须同步更新组件映射、降级展示、类型注释、测试用例或验收说明。

## 申贷确认规则

未确认贷款页应复用一套组件。首贷/复贷差异按目标项目现有实现表达，至少检查：

- 产品列表来源：首贷取首页产品配置，复贷取产品详情中的授信订单产品配置。
- 埋点 code：首贷和复贷分别使用各自事件码，不能混用。
- 申贷接口入参：金额、天数、期数、额度产品 ID、营销产品 ID、产品类型、设备信息、广告信息必须符合现有接口约束；本次涉及新文档替换时必须按接口文档映射。
- 提交成功后：
  - 首贷按 App 约定触发“首贷申请成功”原生回调。
  - 复贷按 App 约定上传申请节点风控数据，并刷新产品详情或页面状态。
- 借款协议统一走 bridge 方法，页面层不直接访问原生全局对象。

金额、期限、期数选择必须从服务端产品列表推导，不能写死。产品匹配优先按“天数 + 期数”精确匹配，再回退到同天数、同期数或第一项。

## App 列表和还款期规则

当首页状态进入“多产品/App 列表”时，列表至少区分：

- 启用产品和未启用产品。
- 还款期和逾期产品。
- 点击还款期产品进入详情前，按项目规则检查权限并上传风控数据。
- 同日只上传一次时，需要使用持久化日期 key 控制，key 名按目标项目已有 storage 规则。

复贷详情页的还款组件必须基于金融订单/还款订单数据，不要从授信订单/申请订单读取还款计划。

## 原生和风控规则

- 原生方法必须统一封装在 bridge hook / utility 中。
- 页面层不要直接调用 `window.flutter.postMessage` 或其他原生全局对象。
- 原生桥接必须遵守 `h5-apply-flow/references/native-methods.md` 的统一桥接协议，页面层不要分散直连原生全局对象。
- 异步原生回调必须保留回调清理和超时兜底，避免多次覆盖全局回调造成悬挂。
- 还款、申贷、协议、返回挽留、页面停留时长等埋点必须与首贷/复贷事件码对应。
- 处理首复贷埋点需求时，必须先读取目标项目现有埋点上传结构和字段名；其他产品或历史项目的请求示例只用于理解语义，不得把示例字段名、事件包装结构或渠道字段迁移到当前项目。
- 没有 key 的点击埋点按目标项目现有“空点击数组/空明细数组”结构上报；如果目标项目没有事件级点击时间字段，应使用立即单独上报来让通用上传时间接近点击时间，不能混入离页批量队列导致点击时间失真。
- 当需求明确“只保留新增页面统计”或新事件码替换旧事件码时，必须搜索并移除同一页面上的旧事件码调用、旧 key 读写、旧停留/协议/提交结果等残留逻辑，只保留需求指定的新事件码。
- 复贷未确认页返回应按产品要求触发挽留弹窗；首贷首页流程不要误触发复贷挽留。

## 验收重点

交付前必须执行 `h5-testing-checklist` 的首复贷专项检查。至少覆盖：

- 如本次涉及接口/字段替换，字段映射表是否覆盖接口地址、请求头、请求入参、响应字段和全局配置字段；如不涉及，标记为跳过。
- 首页顶层状态码到组件映射。
- 产品详情页的授信/金融订单分支。
- 首贷/复贷数据源切换。
- 未确认页金额、期限、期数、协议、提交。
- 首贷成功原生回调和复贷风控上传。
- 埋点字段结构使用目标项目真实定义；无 key 点击事件使用空数组并按点击时机上报；如新增统计替换旧统计，旧事件码和旧 key 逻辑已无残留。
- App 列表启用/未启用/还款期/逾期跳转。
- 放款中、放款失败、审核中、审核拒绝等状态的数据读取。
- 真实 App WebView 中原生回调、权限、风控上传、协议跳转和返回拦截。
