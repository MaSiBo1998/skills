# 警方新闻线索手动雷达

本协议只在用户明确要求“扫一下警方微博”“查警方最新通报”“从警方账号找新闻”“手动获取警方线索”等时执行一次。它是人工触发的公开信息检索流程，不是后台监控服务。

## 手动触发边界

- 每次扫描都必须由用户在当前任务中明确发起；扫描结束即停止。
- 禁止创建定时任务、轮询、心跳、后台进程、自动通知或自动续扫；不得把“以后关注警方新闻”理解成授权自动抓取。
- 不自动关注、取关、分组或互动。用户另行要求关注账号时，先展示已核验清单并等待一次外部操作确认；单批最多 20 个，出现验证码、安全提示或关注限制立即停止。
- 只读取公开页面或用户已登录浏览器中可见的信息，不读取、导出或持久化 Cookie，不绕过验证码，不下载完整视频，不采集无关个人信息。
- 默认只输出候选卡，不自动写稿、发布、评论、转发或私信。用户选中候选后，才回到主 Skill 的事实核验与写作流程。

## 单次扫描流程

1. 确认本次时间范围。用户说“最新”时默认查看过去 6 小时；用户说“今天”时按北京时间当日 00:00 至当前时间；用户指定范围时按指定范围执行。
2. 优先打开用户已登录微博里的 `警方线索` 分组；分组不存在或账号未纳入分组时，再从已核验账号注册表或公开搜索逐个查看。登录失效、页面验证或访问限制时停止该来源并报告，不切换账号、不绕过限制。
3. 账号至少满足两项才可作为警方来源：微博机构认证；简介明确属于公安机关；上级公安账号存在可核验关联；主体名称与行政区匹配。排除民警个人号、退休人员号、仿冒号、长期停更号，以及消防、法院、检察院等非警方来源。
4. 读取时间范围内的最新公开微博，记录微博 ID、账号、行政区、警种、发布时间、采集时间、原文 URL、500 字以内摘录、事件地点、事件类型、媒体形式和是否原创/转发。不得持久化完整转载正文。
5. 先按微博 ID 去重，再按 `事件主体 + 地点 + 事件日期 + 事件动作` 合并同一事件。多地转发保留最早原创来源、传播地区数和全部来源 URL；旧案重发必须显示原始事件时间。
6. 使用下方 100 分模型评分并执行风险门槛。热榜只用于判断是否开始发酵，不能替代警方原始来源，也不能单独提高新闻价值。
7. 只返回本次新出现的 65 分以上候选，默认最多 3 条；50-64 分只记为观察项，低于 50 分忽略。没有合格新线索时直接说明，不拿日常宣传凑数。
8. 候选选中后补充第二来源、完整通报或后续官方回应，再进入文章写作。警方微博是原始线索，不自动等于事实链完整。

## 评分与过滤

满分 100 分：

- `公共影响 20`：影响人数、区域、公共安全或公共服务范围。
- `异常或冲突 20`：反常行为、强弱冲突、责任争议或明显反转。
- `普通人代价 15`：生命安全、财产、时间、工作、尊严或选择权损失。
- `官方证据完整度 15`：通报主体、时间地点、处置阶段、数字、图片或视频是否完整。
- `时效 15`：是否为新发通报、新进展或仍在快速扩散的事件。
- `独特性及后续空间 15`：是否未被广泛报道、存在跨地区关联、后续回应或责任追问空间。

分级只表示本次人工扫描中的优先级：

- `80-100`：最高优先候选，本次扫描先展示；不触发即时通知。
- `65-79`：普通候选。
- `50-64`：入库观察，不展示为写作候选。
- `<50`：忽略。

日常交通提醒、天气转发、反诈口号、节日宣传、比赛培训、寻物、重复普法、没有具体事件的工作动态，最高按 49 分处理。涉及未成年人隐私、自杀细节、裸露影像、普通人身份曝光、未定罪案件身份定性或单方指控时进入 `风险暂缓`，无论总分多高都不得直接推荐写稿。

## 手动筛选器

`scripts/police_radar/manual_triage.py` 只处理人工采集的 JSONL，不包含任何网络请求或浏览器控制。默认把去重状态写入用户目录下 `.codex/police-radar/police-radar.sqlite`，运行数据不进入 Skill 仓库。

每行至少包含：

```json
{"weibo_id":"123","account_uid":"456","account_name":"某地警方","verified_signals":["机构认证","主体与行政区匹配"],"posted_at":"2026-07-24T10:00:00+08:00","collected_at":"2026-07-24T10:15:00+08:00","url":"https://weibo.com/...","excerpt":"500字以内摘录","event_subject":"事件主体","event_location":"事发地","event_date":"2026-07-24","event_action":"通报的核心动作","source_type":"original","region":"地区","media_type":"图文","scores":{"public_impact":18,"abnormal_conflict":17,"ordinary_cost":12,"official_evidence":14,"freshness":15,"novelty_followup":12},"why_valuable":"可能发酵的原因","ordinary_relevance":"与普通人的关系","needs_verification":["案件所处司法阶段"],"suggested_angle":"建议追问角度","risk_flags":[],"routine_flags":[]}
```

调用示例：

```powershell
python scripts/police_radar/manual_triage.py .\manual-police-posts.jsonl --format markdown --limit 3
```

如果只是临时验证、不写去重状态，可增加 `--no-state`。不得为这个脚本配置计划任务或循环调用。

## 候选卡协议

```markdown
### P1. [事件标题或一句话概括]

- 原微博：[URL]
- 发布时间：[绝对时间]
- 警方账号与地区：[账号｜地区]
- 事件摘要：[只写公开通报能够确认的事实]
- 评分：[总分；六项拆分]
- 为什么可能发酵：[公共影响、异常冲突或后续空间]
- 普通人关联：[安全、财产、时间、权益或规则公平]
- 仍需核验：[第二来源、完整通报、司法阶段、当事方回应等]
- 建议写作角度：[事实允许的追问，不提前定罪]
- 风险提示：[隐私、未成年人、单方说法、旧案重发或阶段混淆]
```

警方线索用于比热榜更早地发现事件；主流媒体、后续通报和热榜用于验证事实是否完整、事件是否开始发酵。不能据此宣称掌握平台推流算法，也不能承诺文章流量。
