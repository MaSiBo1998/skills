# 番茄公开章节实读拆书

## 适用范围

番茄作品详情页和无需登录即可正常打开的章节页可以直接阅读并用于创作结构分析。用户不需要为访问公开网页反复声明“非商用”“本人拥有”或其他授权状态。

公开章节实读的目标是弄清故事怎么运转，而不是只根据书名和简介猜测。正常打开页面、阅读章节、记录抽象分析结论即可；不要调用隐藏接口、绕过登录/验证码，也不要批量镜像或在项目中保存整本原文。

## 两种拆书深度

### 快速市场实读

用于判断当前赛道真实内容方向。每个目标赛道至少选择：

- 新书榜 2 本：观察近期点击入口和前期节奏；
- 阅读榜中公开标记完结的作品 2 本：观察阶段扩张和收束能力；
- 若没有足够完结样本，明确写样本不足，不用连载书冒充。

每本先读连续章节块，而不是只看分散章节标题：

- 第 1–5 章：开局启动器、第一次主动选择、首个兑现；
- 第 8–12 章：短循环是否形成、人物关系是否开始变化；
- 完结书再读一个中段连续块和最后 3–5 章：舞台升级、长线回收和结局兑现。

### 单书深度实读

用户指定某本公开小说时，先读取目录总章数，再按长度制定样本：

| 作品进度 | 最低样本 |
| --- | --- |
| 50 章以内新书 | 第 1–10 章 + 最新 3 章 |
| 50–200 章连载 | 第 1–10 章 + 首个阶段转折连续 5 章 + 最新 3 章 |
| 200 章以上连载 | 第 1–10 章 + 约 25%/50%/75% 位置各连续 3 章 + 最新 3 章 |
| 已完结作品 | 第 1–10 章 + 约 25%/50%/75% 位置各连续 3 章 + 最后 5 章 |

目录标题只能用于定位转折，不能代替阅读章节内容。需要对整本作品给出精确逐卷结论时，优先使用用户提供的本地全文；公开网页模式仍可逐段继续读，但必须记录实际覆盖范围，不能把抽样结论说成全书事实。

## 浏览器执行

1. 打开 `https://fanqienovel.com/page/<book-id>`，读取作品名、简介、总章数、更新状态和公开目录。
2. 只跟随页面正常提供的 `https://fanqienovel.com/reader/<chapter-id>` 链接。
3. 页面文本若能正常读取，直接在当前上下文分析；若 DOM 使用自定义字体映射，查看章节页面截图，以视觉方式阅读。不要拿私用区乱码推断剧情。
4. 每读完一个连续章节块，立即把抽象事实写入 `analysis-ledger.json`，再继续下一个块，避免长篇上下文漂移。
5. 遇到登录、验证码、章节不可见或访问限制时正常停止，记录覆盖到哪里；不尝试绕过。

公开章节模式初始化：

```powershell
python scripts/init_source_analysis.py `
  --project-dir <项目目录> `
  --source-kind public_web `
  --source-label <书名> `
  --source-url https://fanqienovel.com/page/<book-id> `
  --materials-scope sampled_public_chapters
```

记录章节块：

```powershell
python scripts/record_source_analysis_chunk.py `
  --project-dir <项目目录> `
  --chunk-id opening-01 `
  --scope-label 第1-5章 `
  --evidence-grade public_chapter `
  --dimensions story_engine,opening_starter,short_loop,opening_hook,chapter_rhythm `
  --abstract-finding <不含原文长摘录的结构结论>
```

## 每个章节块必须记录

- 覆盖章节号、章节标题和访问 URL；
- 主角阶段目标、即时阻力、主动选择和选择代价；
- 本块发生的关键事件及因果，不抄原句；
- 新增信息、延后信息、人物知识差；
- 人物关系发生了什么可验证变化；
- 每章的兑现类型和章末钩子类型；
- 本块形成了怎样的短循环，下一块需要验证什么；
- 证据状态：已实读 / 仅目录定位 / 尚未验证。

## 输出要求

公开章节实读报告必须分成三层：

1. **已验证事实**：来自实际读过的章节块；
2. **结构推断**：由多个连续块共同支持，但仍需后续章节验证；
3. **未验证部分**：没有阅读覆盖，明确留空。

最终要回答故事发动机、短中长循环、人物关系发动机、冲突升级、信息揭示、章节节奏、爽点成本和失速风险。不要反复向用户输出版权声明；直接说明读了哪些章节以及结论即可。
