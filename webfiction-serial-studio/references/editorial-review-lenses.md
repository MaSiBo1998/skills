# 编辑审稿镜头

本文件吸收已审阅第三方写作 skill 中不冲突的方法，只作为 `webfiction-serial-studio` 的审稿辅助。不得覆盖本 skill 的番茄赛道、原创分离、状态门禁、章节钩子、导图和 `series-state.json` 唯一事实源规则。

## 审稿顺序

每次修正文或续写前，按下面顺序看问题，不要先润句子再补逻辑：

1. **结构审稿**：本章是否有 POV 目标、阻力、选择、结果；结果是否推动下一章，而不是只顺序发生。
2. **人物审稿**：关键行动是否能回答“他想要什么、为什么现在这么做、如果失败会损失什么”；人物是否按自己的知识边界和关系位置说话。
3. **连续性审稿**：人物地点、时间、已知信息、情绪余波、道具/钱/合同状态是否接得上上一章。
4. **行文审稿**：删解释型排比、概念定义、标签式对照句、同质化台词、空泛情绪词和重复句式。

## 场景级四问

每个正文场景至少回答：

- POV 此刻想达成什么具体结果？
- 谁或什么阻止他？
- 他做了什么选择，付出或承担了什么？
- 场景结束后，订单、现金、商户、关系、信息、工具、时间线或读者承诺哪一项发生变化？

无法回答第四问的场景，优先合并、改写或删除。

## 人物动机链

对突兀行为追问到可落地为止：

`行为 -> 眼前目标 -> 更深动机 -> 已有经历/利益/关系 -> 失败代价`

都市商业爽文里，“主角知道未来”只能解释方向，不能替代执行动机。周野的每次选择还必须落到钱、时间、家庭、自由、组织边界、人才、商户或时代限制上。

## 知识状态与情绪余波

连续性不仅是时间线，还包括：

- 谁知道了什么，什么时候知道的，谁还不知道；
- 上一章的惊讶、怀疑、疲惫、兴奋或利益变化，本章是否有自然余波；
- 角色不能提前引用尚未发生的信息，也不能对重大事件瞬间无感；
- 情绪可以被快节奏压缩，但不能被跳过。

## 行文去模型腔

行文审稿优先处理：

- “什么叫 A，什么叫 B，什么叫 C”；
- “他知道/明白/清楚……效率、产品、时代、商业”；
- “他本能地看见/判断/拆解……”；
- “不是 X。而是 Y。”或“不是 X，而是 Y”替读者总结主题；
- 连续三句同长度、同语气、同逻辑的排比；
- 人物对话互相解释设定，而不是带着目的互相试探、成交、拒绝或施压。

优先用现场动作、具体物件、报错、账目、合同、价格、对方反应和后果替代抽象总结。
