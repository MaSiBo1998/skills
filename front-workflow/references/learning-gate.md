# Learning Gate

`learning_gate` 是普通业务任务交付前的固定收口步骤。它只判断是否出现 KB 或 workflow 沉淀候选，不直接写文件。

## 候选信号

- 重复人工修正。
- 遗漏验收。
- 新 app 文档规则。
- 新接口模式。
- 发布规则变化。
- 未知/复合需求兜底后形成稳定判断标准。
- 用户反馈“自动沉淀/自动学习没有触发”。

## 输出规则

- 无候选：交付写明“暂无可沉淀项”。
- 有 KB 候选：输出 KB 沉淀提案，等待用户确认后才写入 `D:\code\my-project\personal-ai-kb`。
- 有 workflow 候选且归属清晰：输出 Workflow 沉淀提案，等待用户确认后才交给 `workflow-self-improvement` 修改、校验和同步运行时。
- 候选归属不清、高风险业务结论、可能固化一次性项目事实、影响多个团队约定或需要补充业务结论时，只列为待确认沉淀项。

## Workflow 沉淀提案字段

| 项 | 内容 |
| --- | --- |
| 沉淀类型 | 场景识别 / 执行顺序 / 验收缺口 / 项目特例 |
| 沉淀方向 | front-workflow / 对应子 skill / h5-testing-checklist |
| 目标文件 | 计划写入的 skill 或 reference |
| 规则摘要 | 准备沉淀的判断标准 |
| 触发证据 | 本轮对话、代码、报错或验收缺口 |
| 风险等级 | low / medium / high |
| 建议动作 | 等待用户确认后写入 / 暂只记录候选 |
