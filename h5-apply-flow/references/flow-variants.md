# 进件流程代际

进件先判业务场景为 Apply，再判流程代际。参考项目只能帮助识别和对照，不能成为唯一事实来源；即使参考项目路径不可用，也必须按本文件的稳定合同继续推进。

## 公共合同

任何进件流程都至少按以下合同处理：

- 入口识别：先确认入口来源和提交后去向，例如首页继续进件、资料补充、首贷入口、复贷入口或项目等价入口。
- 步骤编排：从目标项目的路由、步骤配置、页面目录、接口状态或 checkpoint 推断步骤顺序；不要凭参考项目硬编码。
- 表单保存：每个步骤都应有表单状态、校验、保存接口、保存成功后的下一步或返回逻辑。
- 草稿与回填：进入步骤页时读取用户详情或步骤详情，保存后更新本地/全局状态；不要新增第二套状态源。
- 子流程：证件、人脸、联系人、银行卡、设备/权限等子流程只在目标项目确实存在时执行；若需要原生方法，按 `native-methods.md` 判断 App 内嵌。
- 键盘遮挡：包含真实输入框时必须处理 App WebView 或移动浏览器键盘遮挡；独立 H5 也要保证输入框不被固定底部按钮遮挡。
- 接口与配置：API base URL、后端接口地址、固定请求头、国家/产品差异优先放 `.env*`；已有 `.env*` 或 Vite `import.meta.env` 时不要新增只 re-export env 的 `src/config/app.js` 薄封装，只有项目既有配置层承担校验、解析、组合或环境映射等真实职责时才复用配置层。
- 精确结构：接口文档、用户示例或现有类型明确时，按固定结构直接取值；不要做多层字段探测和旧字段兜底。

## 旧流程

参考项目：`D:\code\H5\Crediapoyo\crediapoyo-step-app`

旧流程用于用户明确说旧流程、项目名/目录/代码结构指向 `crediapoyo-step-app`，或目标项目结构明显是 step-app 形态时。稳定处理规则：

- 以“步骤页 + 保存后跳转下一步”为核心模型。
- 优先从目标项目自身的 step 配置、路由和保存接口识别步骤，而不是假设 Confiq-H5 的步骤顺序。
- 旧流程如存在原生方法、bridge 或 window 回调，才判定为 App 内嵌；否则按普通移动 H5 处理。
- 参考项目存在时，只用来对照目录、交互和步骤组织方式；字段、接口和路由仍以目标项目为准。

## 新流程

参考项目：`D:\code\H5\Confiq\confiq-h5`

新流程用于用户明确说新流程、Confiq-H5、当前新进件，或目标项目结构与 Confiq-H5 一致时。稳定处理规则：

- 以国家 profile、Entry 来源、步骤状态接口、拍摄/联系人子流程、保存后去向为核心模型。
- 国家差异只放到 country profile；不要为每个国家新建独立进件 skill。
- Confiq-H5 的具体字段、接口和步骤顺序是参考事实，不是所有新流程的硬编码默认；目标项目已有代码和接口文档优先。
- 若用户提供准确数据结构或类型，按该结构直接取值，不套旧流程兼容。

## 参考项目缺失 fallback

如果 `D:\code\H5\Crediapoyo\crediapoyo-step-app` 或 `D:\code\H5\Confiq\confiq-h5` 不存在：

1. 不因参考项目缺失阻断。
2. 先读取目标项目证据：`package.json`、路由、页面目录、steps 配置、API 封装、types、环境变量、现有 bridge、design、checkpoint。
3. 若用户已说明旧流程或新流程，按对应稳定处理规则执行，并在交付中记录“参考项目不可用，已按抽象合同 + 目标项目证据处理”。
4. 若旧/新流程无法从用户输入和目标项目证据判断，才问一个最小阻塞问题：“本次进件按旧流程还是新流程处理？”
5. 不凭记忆补参考项目里的字段、接口、路由或组件名；缺少这些具体事实时，只能从目标项目或接口文档确认。

## 禁止项

- 不把参考项目路径当成必须存在的运行依赖。
- 不把旧流程字段/接口硬套到新流程，也不把 Confiq-H5 规则硬套到旧流程。
- 不因为出现“进件”就判定为 App 内嵌；只有原生交互证据才能判定。
