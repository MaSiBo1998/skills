# h5-embedded-app-workflow

> *基于现成 H5 内嵌 app 基准项目复现新项目的 Claude Code 工作流。*

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Claude Code](https://img.shields.io/badge/Claude%20Code-Skill-blueviolet)](https://claude.ai/code)

<br>

**适用于：已有 H5 内嵌 app 项目作为基准，后续按基准项目复现一个新项目，并导入新的接口文档、新参数、新设计稿完成开发与模拟验收。**

<br>

这个 Skill 重点解决 4 件事：<br>
基准项目复用、基于接口文档自动识别字段对应关系、Figma 一比一还原，以及最后的模拟测试验收。<br>

## 效果示例

### 问：这个 H5 项目是基准项目，这次要参考它复现一个新项目，并导入一套新的接口文档，返回结构差不多，但参数名变了，你直接做完

```text
Claude Code  ❯ 我会先分析基准项目的接口封装、页面结构和复用模块，
               再对照导入的接口文档整理新项目的请求地址和参数名变化。

               如果返回结构和业务语义保持一致，我会基于接口文档
               在新项目的接口层或数据适配层完成对应关系适配，而不是把基准项目逻辑整体推翻重写。
```

### 问：这是新的 Figma 设计图，按基准项目的结构复现一个新的 H5 项目，并把样式做成一模一样

```text
Claude Code  ❯ 我会先识别当前项目里的布局组件、按钮、表单、卡片和样式变量，
               优先复用现有体系。

               然后按 Figma 的布局、间距、字号、颜色、状态样式做高还原，
               最后检查页面展示和交互一致性。
```

### 问：开发完以后你要自己模拟测试一下，通过测试验收再交给我

```text
Claude Code  ❯ 完成开发后我会补一轮模拟测试：
               包括请求地址、参数映射、页面渲染、表单校验、空态、异常态、
               交互流程和构建/Lint 能力范围内的检查。

               最后会把已验证项、未验证项和建议你手动验收的部分整理出来。
```

## 适用场景

这个 Skill 适合以下项目模式：

- 已有一个可运行的 H5 内嵌 app 基准项目
- 需要以这个基准项目为蓝本复现一个新项目
- 业务模型相似，接口返回结构和取值语义大体一致
- 新项目会更换接口地址、请求参数名、页面设计稿
- 需要根据导入的接口文档 + Figma 快速完成一轮可靠开发
- 用户导入完接口文档文件和 Figma 文档后，希望 Claude Code 连续完成全部开发任务

## 工作流

这个 Skill 会驱动 Claude Code 执行以下流程：

1. 识别当前基准 H5 项目和可复用模块
2. 基于基准项目规划新项目的复现范围和改动点
3. 导入接口文档，识别地址变化、参数名变化和返回结构关系
4. 基于接口文档在新项目的接口层或适配层完成字段对应处理
5. 在接口文档和 Figma 信息齐备后进入连续开发模式，不再反复询问
6. 按 Figma 设计稿高还原实现新项目页面
7. 完成模拟测试与验收清单整理

### 接口文档导入优先级

为了让字段识别和结构比对更稳定，推荐按以下优先级导入接口文档：

1. `swaggerApi.json`
2. `api.json`
3. `api.md`
4. `api.html`

推荐原因：
- `swaggerApi.json` 结构最标准，最适合作为工作流主输入
- `api.json` 适合补充 YApi 原始字段信息
- `api.md` 适合人工查阅
- `api.html` 更偏展示，不适合作为主解析来源

### 标准输入

建议一次性提供以下资料：

1. 基准 H5 内嵌 app 项目代码
2. 接口文档文件，优先 `swaggerApi.json`
3. Figma 链接或设计图文件
4. 如有测试约束，补充测试账号、环境说明、验收重点

## 设计原则

- **先复现，再调整**：优先基于基准项目复现新项目的页面和逻辑
- **先读文档，再适配**：参数名变化优先依据接口文档完成适配
- **先收齐资料，再连续执行**：拿到接口文档和 Figma 后默认一口气做完
- **先局部改，再全局动**：控制改动边界
- **先高还原，再谈优化**：优先满足设计一致性和交付可验收
- **先模拟测试，再交付**：必须给出测试与验收说明

## 使用方式

```text
用 H5 基准项目复现工作流帮我做这个需求
```

```text
基于这个 H5 基准项目复现一个新项目，并导入新的接口文档完成开发
这个接口结构一样，但参数名变了，你按基准项目复现并改好
按新的 Figma 设计稿把这个新项目页面一比一做出来，并模拟测试验收
```
