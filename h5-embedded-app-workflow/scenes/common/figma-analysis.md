# 设计图自动分析

## 核心原则

设计分析必须结合基准项目，不能脱离基准项目只看 Figma。

## 输入方式与自动检测流程

工作流按以下顺序自动决定设计图来源：

1. **用户已提供 Figma 链接** → 执行方式一（Figma API 在线分析）
2. **未提供 Figma 链接** → 自动检测项目根目录是否存在 `designs/` 文件夹：
   - 存在 → 自动执行方式二（本地设计图分析），无需询问用户
   - 不存在 → 询问用户：提供 Figma 链接 / 将截图放入 `designs/` 目录 / 跳过本步骤

### 方式一：Figma API（在线）

前置检查：确认 `$FIGMA_TOKEN` 环境变量已设置，未设置则提示用户先配置 Figma Access Token。

使用 Figma REST API 获取设计文件信息：

```
file_key:  从 URL 提取 https://www.figma.com/design/{file_key}/{title}?node-id={node_id}
node_id:   从 URL 提取（可选）

获取完整文件:  curl -s -H "X-Figma-Token: $FIGMA_TOKEN" "https://api.figma.com/v1/files/{file_key}"
获取指定节点: curl -s -H "X-Figma-Token: $FIGMA_TOKEN" "https://api.figma.com/v1/files/{file_key}/nodes?ids={node_id}"
```

关键字段：`document.children`、`node.type`、`node.absoluteBoundingBox`、`node.fills[].color`（范围 0-1，转 0-255 需 *255）、`node.style`、`node.characters`、`node.effects`。

**限流处理**：Figma API 可能返回 429 (Rate Limit Exceeded)。首次请求失败后等待 60 秒重试，最多 3 次。如果仍然失败，自动切换到方式二。

### 方式二：本地设计图文件夹（离线/限流降级）

当 Figma API 不可用（Token 未配置、限流、网络问题）时，或用户主动要求使用本地文件时，使用本地文件夹中的设计截图进行分析。

**触发条件**（满足任一即使用此方式）：
- Figma API 返回 429 超过 3 次
- `$FIGMA_TOKEN` 未设置且 `designs/` 文件夹存在
- 用户主动指定使用本地设计图

**Figma URL 与本地 `designs/` 同时存在时的优先级规则**：
- 用户显式指定使用其中一种 → 以用户指定为准
- 用户未指定 → Figma API 优先（尝试方式一，失败后自动回退到方式二）

**约定目录结构**：
```
designs/           ← 设计截图（页面级别的完整截图）
  home.png         ← 首页
  login.png        ← 登录页
  status-xxx.png   ← 各状态页
  ...
designs/cutouts/   ← 需要的切图素材（图标、背景等）
  icon-xxx.png
  bg-xxx.png
  ...
```

### 截图质量与准备建议

本地设计截图的清晰度和完整性直接影响分析质量。推荐按以下规范准备截图：

- **分辨率**：移动端设计截图宽度 **≥ 750px**，确保文字和边界清晰可辨
- **完整性**：每个页面截取完整内容（含顶部导航到底部安全区），避免仅截取局部
- **命名**：按页面功能英文/拼音命名（`home.png` / `login.png` / `apply-step1.png`），便于理解页面关系
- **格式**：PNG 优先于 JPG（文字边缘更清晰）；如使用 JPG，质量 > 80%；**不支持 PDF/SVG/GIF**
- **流程覆盖**：如有交互流程，按用户操作路径截取完整页面序列
- **切图素材**：需要前端直接使用的图标/背景图放入 `designs/cutouts/`，无需分析

**分析流程（四遍分析法）**：

以下四遍分析按顺序执行，前两遍逐张图片操作，后两遍跨页面综合分析。

#### 第 1 遍：页面布局扫描（逐张）

对每张截图，先做整体结构扫描：

1. **识别视口类型**：移动端设计（典型宽度 375pt/414pt）→ 标注页面上下边界；桌面端/平板设计 → 标注非居中区域的起始位置

2. **自上而下划分布局区域**：
   ```
   ┌─ [页面名称] ─────────────────────────────┐
   ├─ 状态栏区域（如有）：信号/时间/电量         │ ← ~5%，H5 内嵌时由原生控制，不实现
   ├─ 导航栏：标题位置 + 返回/操作按钮           │ ← ~8-10%
   ├─ 步骤条/Tab 栏（如有）：选项 + 选中态        │ ← ~6-8%
   ├─ 主内容区：列表/表单/卡片/图表等内容区域     │ ← ~55-70%
   ├─ 底部操作栏（如有）：按钮/TabBar/安全区     │ ← ~10-15%
   └─ 弹窗覆盖层（如有）：模态框/底部抽屉         │ ← 视情况而定
   ```

3. **输出布局结构图**：用缩进文本画出每张截图的结构，标注各区域内容（见上例格式）

#### 第 2 遍：组件级识别（逐张）

在第 1 遍的布局基础上，逐区域识别具体组件类型和属性：

**导航类**：导航栏标题位置（左/中/右）、有无返回按钮、右侧操作按钮；步骤条数量与当前位置；Tab 项数、选中项、红点/角标

**表单类**：输入框标签位置（上/左）、占位符内容、前缀图标、清除按钮；选择器展开方式（弹窗/下拉/底部抽屉）；开关/复选框样式与选中态颜色；错误提示位置与样式

**数据展示类**：列表结构（单行/多行、前缀图标/头像、右箭头）；卡片圆角与阴影、内容排布；网格列数与间距；标签/徽章位置、颜色、形状

**操作类**：按钮类型（主/次/文字/图标）、状态（可点击/禁用/加载中）；FAB 位置与展开方式

**弹窗/浮层类**：弹窗类型（Alert/ActionSheet/全屏弹窗/底部抽屉）、遮罩颜色与透明度、关闭方式

#### 第 3 遍：样式提取（跨页面统一）

所有截图分析完毕后，**跨页面汇总**提取统一的样式 token。每个值标注置信度（见下方置信度规则）：

1. **色彩体系**（跨页面归并）：
   - 主色（出现频率最高的色调）、辅色、背景色（页面/卡片/弹窗）
   - 文字色层级（一级 `~#333` / 二级 `~#666` / 提示 `~#999`）
   - 边框与分割线色、功能色（成功绿/警告橙/错误红/链接蓝）
   - 渐变色标注方向与起止色
   - 注：纯色直接给出，渐变色标注方向与起止色，所有值标记 `[估计值]`

2. **字号层级**（跨页面统一）：
   ```
   | 层级 | 典型用途 | 估计值 |
   |------|---------|--------|
   | H1 | 页面大标题 | 20-24px 粗体 |
   | H2 | 卡片/弹窗标题 | 16-18px 中粗 |
   | Body | 正文/列表项 | 14-15px 常规 |
   | Caption | 辅助说明 | 12-13px 常规 |
   | Label | 标签/角标 | 10-11px 常规 |
   ```
   - 以相对比例为主（如"标题比正文大 4px"），辅以估计像素值
   - 如有明确参照物（如按钮高度通常 44px），可通过比例推算并标注 `[估计值]`

3. **间距体系**：页面左右边距、列表项间距、表单字段间距、卡片内边距、按钮高度与内边距

4. **圆角体系**：大圆角（弹窗/卡片）、中圆角（按钮/输入框）、小圆角（标签/徽章）、半圆角（胶囊按钮 → 标注 50%）

5. **图标风格**：线型/面型/双色、相对于文字的大小、颜色规则

6. **阴影与层级**：卡片阴影方向与大小、弹窗遮罩透明度估计、浮动元素层级推断

#### 第 4 遍：交互流程推断（跨页面）

所有页面分析完毕、样式统一后，综合推断交互流程：

1. **页面顺序与导航路径**：按文件名或视觉内容确定页面顺序，推断跳转关系，标注并列/递进关系

2. **触发行为**：按钮点击 → 跳转/弹窗/提交；列表项点击 → 详情页；表单提交 → 下一步；返回 → 上一步/退出

3. **状态变化**：正常态 → 加载态 → 成功态/错误态/空态。区分页面初始状态与操作后状态

4. **弹窗触发逻辑**：何时弹出、弹窗内操作、关闭后的页面状态

**分析置信度标注**：

在分析结果中对每个提取值标注置信度等级：
- **✅ 确定**：能从截图中明确辨认（如纯色背景的主色、清晰可见的文字颜色）
- **⚠️ 存疑**：视觉上可推测但无法精确判断（如字号、间距的精确 px 值）→ 加 `[估计值]` 前缀
- **❓ 需确认**：无法从截图中确定（如点击态样式、动画时长）→ 在最终报告中单独列出"待确认事项"

**设计稿设备框架处理**：

- 如果截图中包含**设备外壳**（iPhone/Android 框），忽略外壳区域，仅分析内部 UI 内容区域
- 如果截图包含**模拟状态栏**（信号/时间/电量），识别为"模拟状态栏"并注明：该区域在 H5 内嵌时由原生 App 控制，不应在代码中实现
- 如果截图已切除状态栏（内容直接贴顶），适配时需添加 `safe-area-inset-top`

**跨页面样式一致性规则**：

分析多张截图时，必须跨页面统一样式 token：
- 跨页面相同视觉元素（如按钮颜色）合并为同一 token，标注`"跨 N 个页面一致"`
- 差异在视觉误差范围内的取值（如一个页面 15px 另一页面 14px），取中间值统一
- 视觉差异 > 30% 的同一属性，分别列出并说明差异所在页面
- 在输出最终 token 表时注明一致性程度

**失败处理**：
- `designs/` 目录不存在 → 提示"未检测到 designs/ 目录，请截图放到 designs/ 目录下，或提供 Figma 链接"
- `designs/` 目录为空或无支持的图片格式 → 提示"designs/ 中未找到 PNG/JPG/WEBP 图片"
- Read 工具读取图片失败（文件损坏/格式不支持）→ 提示"部分图片读取失败，请检查截图文件是否完整"，列出失败文件名
- 单张截图清晰度不足（模糊/分辨率过低）→ 对此图片标注"清晰度不足，仅分析可辨认部分"，输出部分分析而非跳过
- 所有图片读取完毕但信息不足以构建设计报告 → 分两种情况：
  - **有部分有效信息**：输出部分报告，标记不精确项为 `[估计值]`，提示用户补充设计描述
  - **完全无法提取信息**：提示"截图内容无法识别为 UI 设计，请提供清晰的设计截图或 Figma 链接"
- 只有一张截图但流程包含多个页面 → 输出布局和样式分析，标注"仅单张截图，无法推断完整交互流程"，建议补全截图
- `designs/cutouts/` 中的文件与页面截图重复 → 跳过重复文件，避免重复分析
- 文件名含非 ASCII 字符导致读取失败 → 提示用户使用英文/拼音重命名

## 设计侧分析（Figma / 本地截图）

- 页面布局结构树（导航、内容区、底部、弹窗）
- 组件类型（列表/表单/卡片/按钮/弹窗/选择器）
- 色值、字号、间距、圆角等样式 token
- 交互流程（页面跳转、状态切换）
- 状态样式（加载/空态/错误态/成功态）

## 基准项目侧分析

- 已有组件体系、移动端适配方案、样式变量、兼容策略
- 评估哪些组件可直接复用、需修改、需新增

## 设计约束

```
H5 内嵌约束:
  - 无顶部状态栏（原生 App 提供）
  - 底部导航不与原生 TabBar 冲突
  - 触摸区域 ≥ 44x44px
  - 内容区适配安全区域（safe-area-inset-*）
  - 避免桌面交互（hover、右键）

浏览器兼容: Android 5.0+ / iOS 10+, ES5, Autoprefixer, Flexbox 优先

加载性能: 首屏 < 1.5s, 路由懒加载, 骨架屏, 资源压缩, hash 指纹
```
