# Demo Conversation

## 示例 1：基准项目二开

### 用户

这个 H5 内嵌 app 项目是旧基准项目，后面都会在这个项目上继续改。你用这个工作流帮我在旧项目基础上开发新需求。

### Claude Code 预期行为

1. 先识别当前项目技术栈、目录结构、公共组件和接口封装。
2. 搜索与新需求最接近的旧页面和旧逻辑。
3. 制定“基于旧实现二开”的最小修改方案。
4. 尽量复用已有模块，不做无关重构。

## 示例 2：接口文档导入与参数适配

### 用户

这是新的接口文档导出文件，请把当前页面改成新接口。返回结构不变，但请求参数名换了。

### Claude Code 预期行为

1. 读取导入的接口文档文件，提取新的请求地址、请求方法和参数名。
2. 对照旧接口封装，识别新旧字段一一对应关系。
3. 优先在接口层或数据适配层完成映射。
4. 检查页面逻辑是否仍可复用。
5. 输出本次接口改造和字段映射说明。

## 示例 3：Figma 还原与模拟验收

### 用户

这是新的 Figma 设计图，按当前 H5 项目一比一做出来，做完以后自己模拟测试一下。

### Claude Code 预期行为

1. 读取设计稿中的布局、间距、字号、色值和状态样式。
2. 搜索项目里可复用的布局、卡片、按钮、表单和弹窗组件。
3. 基于现有样式体系完成高还原实现。
4. 检查交互、空态、异常态、按钮状态和请求联动。
5. 产出一份模拟测试与验收说明。

## 示例 4：资料齐备后连续开发

### 用户

这是新的接口文档文件和 Figma 文档。你直接基于当前 H5 基准项目把这个需求完整做完，不要中途反复问我。

### Claude Code 预期行为

1. 读取接口文档文件并识别新接口地址、参数名和返回结构关系。
2. 读取 Figma 文档并提取布局、样式和交互要求。
3. 默认进入连续执行模式，基于旧项目直接完成分析、开发、自检和模拟测试。
4. 仅在链接失效、信息冲突、权限不足或无法继续执行时才提问。
5. 最终一次性交付修改说明、测试结果和待用户验收项。
