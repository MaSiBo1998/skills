# 01 Positioning

## 定位

`h5-embedded-app-workflow` 用于处理三类项目模式：

### 场景 A — 架构改造
- 已有项目，需要改造构建架构
- 不改业务代码
- 建立 static-app/ 基线依赖 + external + 双模式路径

### 场景 B — 首复贷功能开发
- 已有基准项目，需要参考其复现新功能
- 新导入的接口文档会变化（地址、参数名）
- 页面设计稿会变化
- 但业务模型和接口返回结构、字段语义基本保持一致

### 场景 C — 进件功能开发
- 现有项目上新增或修改进件申请流程
- 只修改 Apply 相关页面和 API
- 含 Figma 还原 + 接口适配 + 可选 vendor 架构

## 核心价值

- 避免脱离基准项目从零摸索新项目
- 把"字段名变了但结构没变"的问题收敛为适配问题
- 提高基准项目在新项目复现中的复用率
- 让设计还原、接口改造和测试验收形成固定流程
- **将 H5 资源加载从网络请求优化为本地文件读取，大幅提升首屏速度**
- **基线依赖一次性打包到 App，后续 H5 更新只需发布业务代码**
