# 03 Figma, Acceptance and Architecture

## Figma 还原原则

- 优先复用基准项目现有组件和样式变量
- 重点还原布局层级、间距、字号、色值、边框、圆角、状态样式
- 在新项目中保持交互一致性和页面层级，优先于盲目新增组件系统
- 设计分析必须结合基准项目，不能脱离基准项目只看 Figma

## 自动测试要求（14 项）

完成开发后必须逐项执行 CHECKLIST.md 中的 14 项检查：

1. 类型检查 — tsc --noEmit
2. Lint 检查 — eslint
3. 构建测试 — npm run build
4. 页面渲染检查 — 组件导入是否正常
5. 路由检查 — 路由配置是否正确
6. 接口请求检查 — 是否指向新地址
7. 参数映射检查 — 逐字段对照映射表
8. 设计还原检查 — 布局/样式/色值对照设计稿
9. 交互流程检查 — 跳转/表单/弹窗
10. 异常态检查 — 加载态/空态/错误态
11. H5 内嵌规范检查 — 无状态栏/触摸区域/安全区域
12. 浏览器兼容检查 — ES5/CSS 前缀/Flexbox
13. 构建架构检查 — DLL + externals + 双模式
14. 性能检查 — 懒加载/骨架屏/压缩

## 验收输出建议

交付时输出：

- 场景 A/B：
  - 基于哪个基准模块或页面完成新项目复现
  - 哪些接口地址已替换
  - 哪些参数名做了映射（附映射表）
  - 哪些页面按 Figma 做了高还原
- 场景 C：
  - 架构改造清单（改了哪些配置文件）
  - 基线依赖清单（static-app/ 包含哪些文件）
- 所有场景：
  - 14 项测试结果
  - 已完成哪些模拟测试
  - 哪些部分需要真实接口或测试环境进一步验证
