# App 内嵌协议/隐私开发

适用于协议/隐私相关的 App WebView 开发问题，例如 App 需要打开隐私协议、授权协议、贷款协议、条款协议，或需要确认 H5 路由、静态 HTML、iframe、官网入口与原生入口如何对齐。

## 输入收集

必须先从项目或用户输入确认：

1. App 要打开的入口类型：隐私、授权、贷款、条款，或多协议聚合页。
2. 当前项目协议来源：`public/*.html` 静态文件、线上绝对链接、`LEGAL_LINKS` 常量、官网路由页面或 iframe 页面。
3. App 侧打开方式：直接 WebView URL、H5 路由、原生 bridge 跳转、后台配置链接。
4. 目标路由模式：项目现有 HashRouter/BrowserRouter、静态 HTML 路径或线上链接。
5. 是否需要兼容官网入口、footer 链接、旧链接或历史 App 配置。
6. 是否涉及 `.docx` 协议文档生成；涉及时转入 `official-site.md` 的协议 HTML 生成流程。

## 判断规则

- App 只需要展示单份协议正文时，优先使用 `public/*.html` 静态协议文件或已确认的线上协议 HTML。
- App 需要在一个页面内切换多份协议时，使用官网协议展示入口流程：Tab + iframe 或项目既有聚合页。
- App 已有后台配置绝对链接时，不擅自改为本地相对路径；只能在用户确认后替换。
- 项目已有 `LEGAL_LINKS`、协议常量或 footer 链接时，优先复用同一数据源，避免官网和 App 链接不一致。
- 本地开发环境中 iframe 跨域不可控时，只验证 iframe 外层 UI 和 `src` 是否正确，不要求注入 iframe 内部样式。
- 如果 App 入口需要原生 bridge，必须按用户提供的方法名和参数实现；没有明确 bridge 协议时，只能列待确认项，不编造固定方法名。

## 实现规则

- 新增协议入口时，优先复用项目已有 `Legal`、协议展示页或静态 HTML 生成规范，不复制多套协议正文。
- 静态协议 HTML 必须移动端可读、无外部 JS/CSS/CDN、语义化标签清晰，正文不得擅自改写法律语义。
- H5 路由入口不得破坏官网导航和页脚；App 专用入口若要求无官网壳层，必须按独立 App 页面处理。
- URL 参数或 query 控制协议类型时，需要提供默认值和旧入口兼容策略。
- 所有外部链接、iframe `src`、App 可访问路径必须在交付中列清楚，方便原生侧配置。
- 如果用户只问开发/验收口径，不做代码改动时，输出应包含：当前项目事实、推荐入口、待确认项、验收路径。

## 验收清单

必须执行或说明无法执行原因：

```text
□ 目标协议入口可访问
□ App 侧目标 URL、H5 路由或静态 HTML 路径明确
□ 协议类型默认值正确
□ 多协议切换时 Tab/参数/iframe src 对应正确
□ 官网入口、footer 链接和 App 链接的数据源一致或差异已说明
□ 旧入口或历史链接兼容策略已验证
□ 移动端 WebView 宽度下可读，无横向溢出
□ 原生 bridge method/value 与用户提供协议一致
□ 构建或类型检查通过
```
