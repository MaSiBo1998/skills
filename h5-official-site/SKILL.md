# H5 官网与挂载页开发

本 skill 负责官网相关多场景任务：协议文档转静态 HTML、官网协议入口/Tab/iframe 展示、App 内嵌官网协议/隐私开发问答、App 内嵌客服/客服问答页，以及独立小 H5 挂载到官网域名下的开发问题。不得擅自改写法律正文。

## 执行方式

1. 判断任务类型：
   - 协议文档转 HTML：收集 4 份本地协议文档、可选协议链接、目标 `public` 目录。
   - 协议展示入口：收集目标路由、默认选中协议、Tab 协议列表、线上协议链接、旧入口兼容要求。
   - App 内嵌开发问答：识别为协议/隐私相关 App WebView、H5 内嵌、原生跳转、链接配置、验收口径问答；需求细节未沉淀前，只做问题归类、读取现有项目实现和风险说明，不编造固定实现规则。
   - App 内嵌客服问答页：识别为 App 内展示客服、客服中心、客服问答、customer-service、服务中心等页面开发；按官网项目真实结构新增 App 专用路由页面，复用官网 FAQ 内容但隔离样式和布局。
   - 独立小 H5 挂载官网域名：识别为官网域名下新增独立 H5、活动页、工具页、落地页或嵌入页；需求细节未沉淀前，先收集挂载路径、构建产物目录、资源前缀、路由模式和部署方式。
2. 按任务类型加载对应 reference：客服问答页加载 `references/app-customer-service.md`；App 内嵌协议/隐私开发问答加载 `references/app-embedded-protocol.md`；其他官网、协议和挂载小 H5 场景加载 `references/official-site.md`。
3. `.docx` 只允许使用已安装的 `docx` skill 解析。
4. 文档转 HTML 时，链接只用于文件命名，不作为正文来源。
5. 协议展示入口时，优先参考同类项目既有实现，使用 Tab 切换 iframe 展示线上协议链接。
6. App 内嵌协议/隐私开发问答按 `references/app-embedded-protocol.md` 执行；需求沉淀完成前，只记录“待沉淀问题、项目事实、最终结论”，不写入官网主 reference。
7. App 内嵌客服问答页按 `references/app-customer-service.md` 执行；若同时给出设计图，配合 `design-image-analysis`、`design-image-restore` 做移动端视觉复原。
8. 小 H5 挂载规则沉淀完成前，必须基于项目现有官网部署方式和用户提供的域名/路径作答，不预设固定构建或发布方案。

## 约束

- 默认只输出西语正文。
- 不追加原始链接页脚，除非用户明确要求。
- 标题和正文必须拆分为独立标签。
- 不引入外部 JS/CSS/CDN。
- iframe 展示线上协议链接时，不强依赖注入 iframe 内部样式；跨域线上链接在本地开发环境会被浏览器拦截，只控制 iframe 外层容器、标题和 Tab UI。
- 独立小 H5 挂载到官网域名时，优先确认 `base`、资源前缀、路由模式、部署目录、旧入口兼容和移动端 WebView 验收方式。
- App 内嵌客服页不得复用或污染官网 FAQ 样式；FAQ 内容可共享，页面布局和交互必须独立。
